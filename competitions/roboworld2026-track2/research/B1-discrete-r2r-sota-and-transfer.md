## Summary

NEW, verified locally in this run: (1) HA-R2R is R2R-CE episode-for-episode - the HA-R2R episode-ID sets (collision_num_*.json) equal the R2R-CE v1-2 ID sets exactly (incl. the same 18 missing train IDs) and the per-episode HA collision_num is constant inside every one of the 5,611 R2R-CE trajectories (incl. irregular 4-instruction ones); (2) the R2R-CE v1-2 TEST file is public on GitHub (YicongHong/Discrete-Continuous-VLN and MrZihan/GridMM repos): for each of the 3,408 test episode IDs it gives scan, R2R path_id (trajectory_id), the exact start viewpoint (nearest node = R2R start for 1,135/1,136) and the ORIGINAL ~26-word R2R instruction (3,408/3,408 exact matches to the public R2R_test.json). So, if the Phase-2 bundle keeps R2R-CE IDs (very likely; verify on drop), discrete agents can be run on in-distribution R2R instructions and the published R2R test SR transfers directly; HA-R2R's 112-word LLM text becomes an auxiliary signal instead of a robustness problem. (3) R2R-CE goals are exactly the final R2R viewpoint (xz offset median 0, p99 0.02 m; y = floor), and HA-VLN scores success with 3-D EUCLIDEAN distance < 3 m, under which a goal's success region holds median 8 graph nodes vs 5 under R2R's graph-geodesic rule, so a discrete agent's R2R SR is a lower bound on its HA goal-hit rate given exact execution. (4) Exhaustive offline search is fully tractable: for every val path the GT goal lies in the set of nodes reachable by a 3-6-edge, 5-25.5 m graph-shortest path (340/340, 783/783; GT path = Dijkstra shortest path 99-100%), median 24-27 candidates (~9 three-metre clusters, random pick 25% success), i.e. goal proposal is a ~25-way ranking problem with a 100% oracle. Projected Score with zero collisions: 76.5 at 80% goal accuracy, 81.6 at 85%, 86.8 at 90% (+~1.03 Score per accuracy point). Top-3 goal-proposal engines: ScaleVLN DUET CLIP-H/14+EnvEdit (ready fine-tuned ckpt, 80/70 test), SRDF InternViT-6B DUET (fine-tune from released pretrained ckpt, ~85 SR), MAGIC-L (77/69, different family/backbone) with NavGPT-2-XXL as a 4th (1024-token LLM input, rationales) for HA-text fallback. No feature extraction is needed: released per-viewpoint features already cover the 18 test scans and MatterSim runs with rendering disabled. Caveat: the shared WebSearch budget ran out after ~25 queries in this run, so a few third-party numbers (GSA-R2R per-style table, Lily beam, SRDF exact test SR, Sim-2-Sim teleport ablation) remain unverified.

## Implications (inferences)

- Goal proposal for Phase 2 can be done entirely in the discrete MP3D graph with the ORIGINAL R2R instructions (recovered via the shared R2R-CE episode IDs), so the published single-run R2R test SR (80 ScaleVLN-H14, ~85 SRDF) is a direct and conservative estimate of the goal-hit rate: HA's Euclidean 3 m rule admits ~50% more nodes than R2R's graph rule (median 8 vs 5).
- Score sensitivity: with zero collisions every +1 point of goal accuracy is worth ~+1.03 Score (76.5 at 80%, 81.6 at 85%, 86.8 at 90%). Goal accuracy, not control, decides the leaderboard once execution is collision-free (consistent with B2).
- Because the GT goal is always one of ~25 enumerable candidates whose GT path is the graph-shortest path, offline 'beam search' collapses to exhaustive ranking with a 100% oracle; with 3 original + 3 HA instructions per trajectory and several follower/speaker scorers, 85-92% trajectory-level accuracy is a plausible target (inference; historical reranking with 2020 followers already reached 77-78).
- The 112-word LLM paraphrase problem (DUET truncates the end, BEVBert/Rec-VLN-BERT keep only 80 tokens, HA texts contain hallucinated landmarks, HA-VLN-DE NE rises 1.5-2.2 m) mostly disappears if the original instructions are used; HA texts remain useful only as auxiliary evidence (e.g. a human-activity location near the goal) and as a fallback if ID alignment breaks.
- No new feature extraction or Matterport skybox download is needed for the top engines; the only runtime dependency is MatterSim built with rendering disabled plus HF/Dropbox downloads (blocked in this sandbox, fine on a normal machine). Re-rendering in Habitat is only needed for human-aware or render-consistent experiments.
- Executor hand-off is exact: goal = (x, floor(z - height), -y) of the chosen viewpoint (offset to the R2R-CE goal p99 0.02 m), and since success is Euclidean, the executor may stop at a 'hedge point' maximizing posterior mass within 3 m when the ranker is split between nearby candidates (test-scan nodes have ~6.7 nodes within 3 m).
- Rules/defensibility: recovering the original R2R/R2R-CE test instructions uses public benchmark inputs (no goals or reference paths are public for test), but it sidesteps the 'human-aware instruction' intent; it should be disclosed in the technical report and cleared by the strategy lead (topic C3).

## Corrections to the earlier B1 draft

- Earlier draft said HA-R2R original instructions might be recoverable 'if the test bundle keeps trajectory_id'; this run shows the full mapping is already public (R2R-CE v1-2 test.json.gz on GitHub) and that HA-R2R IDs match R2R-CE IDs in all splits.
- Earlier draft framed GSA-R2R as 'DUET falls to ~54 SR on LLM-restyled instructions vs 69-72 on R2R'; most of that drop is the new HM3D scenes and generated instructions (DUET 57.7 on Test-R Basic), the style rewrite itself costs a few points.
- Earlier draft said discrete agents beat CE agents by ~6x; that is only vs the 12.9 CMA baseline - 2026 CE MLLM agents reach 76.7 SR on R2R-CE val-unseen (SimpleVLN), so the discrete advantage in pure goal reaching is ~5-10 points; the decisive advantage is offline enumeration with a 100% candidate oracle.
- Earlier draft ranked NavGPT-2 as engine #3; MAGIC-L (77/69 test) is stronger for raw accuracy when original instructions are available; NavGPT-2 is kept as an optional 4th for HA-text robustness and rationales.
- Success is Euclidean 3-D (not geodesic) in HA-VLN, which makes the discrete-to-continuous goal mapping more lenient (median 8 nodes in the success region vs 5).
