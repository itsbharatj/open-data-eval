# HA-R2R / VLN-CE episode record schema, Phase-2 test-bundle expectations, and trajectory grouping of the 3,408 test episodes

topic_id: `A1-episode-format-and-test-split`

## Summary
An HA-R2R episode is a VLN-CE `VLNExtendedEpisode` (HA-VLN task.py is byte-identical to jacobkrantz/VLN-CE task.py): required keys episode_id, trajectory_id, scene_id ('mp3d/<scan>/<scan>.glb'), start_position [x,y,z], start_rotation [qx,qy,qz,qw], instruction{instruction_text, instruction_tokens}; optional goals[{position,radius}], reference_path, info; the file also carries instruction_vocab.word_list (5,079 words). The loader would KeyError without trajectory_id (task.py L91) but tolerates missing goals (L104), so the Phase-2 test.json.gz will carry id/start-pose/instruction/trajectory_id and (per VLN-CE's documented test split and the website) no goals/reference paths. VERIFIED from the public collision_num_test.json: test episode IDs are the contiguous strings '1'..'3408' and the per-episode baseline collision number is IDENTICAL within every block {3k+1,3k+2,3k+3} (1136/1136 blocks; 79 non-zero blocks; boundary pairs co-non-zero only 8%), i.e. test episodes 3k+1..3k+3 are the three instructions of ONE trajectory: 3,408 episodes = 1,136 trajectories (val_unseen 1,839 = 613 x 3 likewise; official README gives 259/613/3,603 distinct trajectories for val_seen/val_unseen/train). The discrete R2R_test.json (1,391 paths x 3 instructions, start viewpoint + heading only) is already in the HA-VLN repo; HA-R2R test = 1,136 ported paths, so each test trajectory can be matched to its R2R path via MP3D->Habitat coordinates (x,y,z)->(x,z,-y) giving 6 instructions per trajectory (3 LLM-rewritten HA-R2R + 3 original R2R, plus FGR2R sub-instruction chunks). Goal candidates per start are discrete nav-graph nodes 3-6 hops / 5-25 m away: median 24 nodes, ~8 three-metre clusters. Ordering evidence suggests trajectories are listed by ascending R2R path_id.

## Grouping strategy
1. Group test IDs into triples {3k+1,3k+2,3k+3} (k=0..1135); verify identical scene_id/start_position/start_rotation/trajectory_id.
2. Match each triple to an R2R_test.json path: convert viewpoint pose (x,y,z)->(x,z,-y), nearest start in xz (|dy| tolerance), heading check; disambiguate shared starts (314 of 908) by token overlap between HA-R2R texts and the 3 original instructions.
3. Per trajectory: 3 HA-R2R + 3 R2R instructions + FGR2R sub-instruction chunks -> one plan -> one action sequence copied to the three IDs.
4. Goal candidates = nav-graph nodes 3-6 hops / 5-25.5 m from the start (median 24; ~8 three-metre clusters).

## Implications
- Phase 2 is effectively 1,136 independent problems, not 3,408: the three episodes of a trajectory share start pose, goal, scene, human layout, baseline collision number and human-influence flag, so an identical action sequence submitted for IDs 3k+1..3k+3 earns identical per-episode scores (modulo wall-clock human animation). Plan once per trajectory using all 3 HA-R2R instructions jointly (and the 3 original R2R instructions once matched), then copy the sequence to the three IDs.
- The goal of every R2R(-CE) episode is a nav-graph node reached by a graph-shortest path of 3-6 edges and 5-25 m; after porting, the VLN-CE goal is that node's navmesh-snapped position. For a given start there are only ~24 feasible goal nodes (~8 three-metre clusters) -> goal inference is a small discrete classification problem, and a 3 m success radius means choosing the right cluster suffices.
- Because the baseline collision number is per trajectory and public for test (collision_num_test.json), teams know for 79 test trajectories that the reference path passes through 1-3 human collisions (hints at human positions on/near the GT route) and for the other 1,057 that any collision is penalised.
- Human placements for the 18 test scans are NOT in the public HA-VLN 2.0 annotations; the HA-VLN 1.0 files in the same repo give 70 candidate human viewpoints in the test scans with ~82% historical carry-over, which is the best public prior if Phase 2 does not ship test-scan human annotations.
- Matching HA-R2R test trajectories to R2R_test.json paths (via (x,z,-y) coordinate conversion + heading + instruction-text overlap) yields 6 instructions and FGR2R sub-instruction chunks per trajectory and also reveals the R2R path_id (useful if trajectory_id is dummy in the bundle).
- Evidence (train 4-instruction-block shift pattern, val_seen 4-block position) indicates HA-R2R lists trajectories in ascending R2R path_id order; if confirmed on the bundle, episode order alone constrains which 1,136 of the 1,391 test paths were ported.
