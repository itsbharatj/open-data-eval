# HA-R2R / VLN-CE episode schema, the Phase-2 test inputs, and how the 3,408 test episodes group into 1,136 trajectories (v2, re-verified)

topic_id: `A1-episode-format-and-test-split`  (v2 supersedes the earlier A1 file; corrections are marked CORRECTS)

## Summary
The public VLN-CE R2R test split is mirrored on GitHub (YicongHong/Discrete-Continuous-VLN, data/datasets/R2R_VLNCE_v1-2_preprocessed/test/test.json.gz, sha256 47ed2aea...). It has 3,408 episodes with only episode_id, trajectory_id, scene_id, start_position, start_rotation and instruction{instruction_text, instruction_tokens}: no goals, reference_path or info. HA-R2R reuses the R2R-CE episode IDs exactly. In train, val_seen, val_unseen and test, the ID sets are identical (including R2R-CE's own 18-ID gaps in train). HA's public per-episode collision_num is also constant inside every R2R-CE trajectory (3,603/259/613/1,136 of them), including the 11 four-instruction trajectories. So HA test episode k is almost certainly R2R-CE test episode k. That means the scene, exact start position, R2R path_id (=trajectory_id), start viewpoint and original R2R instruction of every Phase-2 episode are known now. The predicted v1-3 start yaw is round30(360 - R2R heading), a rule that holds for 1,839/1,839 val_unseen episodes. Test IDs '1'..'3408' form 1,136 triples {3k+1,3k+2,3k+3}. Each triple shares a trajectory, scene and start pose, and its 3 R2R instructions appear in R2R order. Group by ID triple or trajectory_id, never by start pose: 580 of the 1,136 trajectories share their start pose (same yaw too) with 1-6 other trajectories that sit elsewhere in the file. 255 of the 1,391 R2R test paths were dropped, and we can now identify them. The test file is grouped by scene (18 blocks) and is NOT sorted by path_id. Train and val are sorted by path_id. The organizers' Oct-14 rules clarification (unmerged branch) limits inference inputs to episode ID, initial pose, instruction, GPS+compass and egocentric RGB-D. Under those rules, cross-episode use of sibling or original-R2R instructions and of test-scene nav graphs is a gray area that needs organizer permission. Q11 implies human_motion.json will exist at test time for rendering, so the Phase-2 bundle probably ships test-scan human placements (medium confidence).

## Grouping strategy
1. Group by ID triple {3k+1,3k+2,3k+3} (k = 0..1135), equivalently by trajectory_id. NEVER group by start pose: 580/1,136 trajectories share a start pose and yaw with other trajectories located elsewhere in the file.
2. Join each triple to R2R_test.json by trajectory_id (= path_id). That gives the start viewpoint, the R2R heading, and the 3 original R2R instructions at the same instruction_index. If trajectory_id is missing or re-keyed, match on exact (scene, start_position) from the index plus text similarity for the 232 shared-start groups.
3. Bookkeeping and sharding: 18 scan shards (use the per-scan counts above). One plan per trajectory can be replicated to its 3 IDs, but every ID needs its own row.
4. Regime-dependent use: compliant runs each episode closed-loop on its own instruction (grouping is for accounting and val diagnostics only). Privileged/permission-gated runs a 6-instruction ensemble and ranks discrete nav-graph goal candidates (median 25, 100% filter recall).

## Implications
- Phase 2 is 1,136 independent navigation problems, not 3,408. The three episodes of a triple share scene, start pose, goal, reference path, human layout, baseline collision number and influence flag. Per-trajectory success therefore moves the Score in steps of 3 episodes, and the effective sample size for local estimates of test performance is ~1,136, not 3,408.
- Everything about Phase-2 inputs except the HA instruction text and the human layout can be pre-staged now. That covers the scene per episode, the exact start position, the start yaw (predicted v1-3 rule), the R2R path_id, the start viewpoint, the 3 original R2R instructions, the dropped-path list, per-scene episode counts for compute sharding, and nav-graph goal candidates. All of it is in the index file. Bundle-day work shrinks to a diff/assert job.
- Start-pose-based grouping is wrong for 51% of trajectories (shared starts with different goals). Any cache keyed by start pose must also be keyed by trajectory_id or ID triple.
- Compliant regime (closed-loop egocentric RGB-D + GPS/compass; organizer Oct-14 clarification): the grouping is mainly bookkeeping. It gives correct episode->trajectory accounting, per-trajectory error analysis on val, and scan-sharded scheduling, and lets every agent run identical scene/start conditions 3 times with different paraphrases (a free robustness probe on val). Using sibling instructions or the original R2R instruction at inference is cross-episode or external information. The Input list does not include it, so it is a gray area.
- Privileged/offline regime (needs explicit organizer permission): matching triples to R2R paths gives up to 6 instructions per goal (3 HA + 3 R2R, plus FGR2R chunks). The goal is a nav-graph node among a median 25 candidates (~9 three-metre clusters) with 100% filter recall, so goal inference becomes small discrete classification that discrete SOTA agents (B1) can solve on the original 26-word R2R text, bypassing the 112-word paraphrase gap.
- The public collision_num_test identifies the 79 trajectories whose reference path passes through a human, and the 1,057 where any human collision is pure penalty. Organizers call collision annotations 'withheld', so (a) the scoring copy may differ from the public file, and (b) using it at inference is likely non-compliant. Use it only for analysis and risk weighting during development.
- If Phase 2 ships test-scan human_motion.json (Q11 suggests it will, for rendering), local replay of test episodes is score-faithful except for the wall-clock animation. If not, local test runs are human-free, and the 1.0 test-scan anchors (70 humans, ~82% persistence) are the only prior. Under the compliant regime that prior is for development and evaluation only, never inference.
